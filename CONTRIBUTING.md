# Contributing

Diplomados utiliza un flujo de desarrollo basado en ramas de trabajo y Pull Requests.

## Flujo básico

1. Actualizar `main`.
2. Crear una rama específica para la tarea.
3. Realizar los cambios únicamente dentro del alcance acordado.
4. Ejecutar las validaciones correspondientes.
5. Crear un Pull Request hacia `main`.
6. Esperar que CI finalice correctamente.
7. Obtener la revisión requerida antes del merge.
8. Integrar mediante Squash Merge.

No se debe desarrollar ni realizar push directamente sobre `main`.

## Convención inicial de ramas

- `feat/<tema>` — nuevas funcionalidades.
- `fix/<tema>` — correcciones.
- `refactor/<tema>` — refactorizaciones.
- `chore/<tema>` — mantenimiento interno.
- `docs/<tema>` — documentación.

Esta guía se ampliará conforme se consolide el flujo colaborativo del proyecto.
